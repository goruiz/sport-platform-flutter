1. VISIÓN GENERAL Y FILOSOFÍA
================================================================================

La app sigue una arquitectura "feature-first" con principios de Clean
Architecture adaptados a Flutter. Cada módulo agrupa verticalmente sus capas
(datos, estado, presentación) sin depender de otros módulos.

PRINCIPIOS FUNDAMENTALES
  - Los módulos son islas: no se importan entre sí.
  - La infraestructura compartida vive en core/ o shared/.
  - La navegación es 100% dinámica: el backend decide el menú.
  - Un solo punto de verdad para colores, textos y endpoints.
  - Estado gestionado con Provider + ChangeNotifier; DI con GetIt.

FLUJO DE ARRANQUE (main.dart)
  ┌─ WidgetsFlutterBinding.ensureInitialized()
  ├─ EasyLocalization.ensureInitialized()
  ├─ setupServiceLocator()     → registra singletons en GetIt
  ├─ registerModules()         → asocia URL → Widget en ModuleRegistry
  └─ runApp(EasyLocalization → SportsPlatform)
       └─ _AppRouter (FutureBuilder)
            ├─ AuthStorage.hasToken() == false  → LoginPage
            └─ UserSession.loadFromStorage()    → HomePage

FLUJO DE NAVEGACIÓN
  Backend /menu
    → MenuService (datasource)
    → MenuItemModel (model con campo `url`)
    → HomePage (construye Bottom Nav + Drawer)
    → AppRouteFactory → ModuleRegistry.buildPage(item)
    → Widget del módulo registrado

4. SISTEMA DE MÓDULOS DINÁMICO
================================================================================

El menú proviene del backend. El frontend no tiene rutas hardcodeadas.

CÓMO FUNCIONA

  1. Al arrancar, registerModules() (core/modules/modules_setup.dart) asocia
     cada URL de módulo con su widget constructor:

       ModuleRegistry.register(ModuleUrls.leagues, (item) => LeaguesPage(item: item));
       ModuleRegistry.register(ModuleUrls.teams,   (item) => TeamsPage(item: item));
       // ... etc.

  2. HomePage carga el menú del backend via MenuService → lista de MenuItemModel.

  3. MenuService separa los ítems:
       item.isNavItem == true   →  _navItems  (Bottom Navigation Bar)
       item.isNavItem == false  →  _menuItems (Carousel de acciones rápidas / Drawer)

  4. Cuando el usuario toca un ítem del Bottom Nav:
       AppRouteFactory.tabForItem(item)
         → ModuleRegistry.buildTab(item)      ← sin Scaffold propio
         → Widget del módulo registrado

  5. Cuando el usuario toca un ítem del menú / drawer:
       AppRouteFactory.navigateTo(context, item)
         → ModuleRegistry.buildPage(item)     ← con Scaffold propio
         → Navigator.push

  Si la URL no está registrada → PlaceholderTab (pantalla vacía en modo desarrollo).
  Agregar un módulo ya existente al menú solo requiere insertar una fila en la
  base de datos. No se toca código.

MODULE_URLS (core/modules/module_urls.dart)
  class ModuleUrls {
    static const teams    = '/teams';
    static const events   = '/events';
    static const rankings = '/rankings';
    static const matches  = '/matches';
    static const reports  = '/reports';
    static const profile  = '/profile';
    static const leagues  = '/ligas';
  }

REGLA: Toda nueva URL de módulo se define aquí primero.

MENUITEMNMODEL (home/data/models/menu_item_model.dart)
  Propiedades clave:
    url            → Coincide con ModuleUrls.X para el registry
    displayName    → translationKey ?? name (soporta i18n)
    isNavItem      → navOrder != null && navOrder > 0
    hasChildren    → children.isNotEmpty (sub-menús)
    iconFromString(name) / iconOutlinedFromString(name) → IconData dinámico

5. NAVEGACIÓN Y ROUTING
================================================================================

No hay un sistema de rutas nombradas (no se usa GoRouter ni routes:[] en
MaterialApp). La navegación es imperativa con Navigator.of(context).push.

DESDE TABS (dentro de home_page.dart):
  // Construye el widget del tab usando el registry
  AppRouteFactory.tabForItem(item)   →  ModuleRegistry.buildTab(item)

NAVEGACIÓN PUSH A PANTALLA NUEVA:
  AppRouteFactory.navigateTo(context, item)

NAVEGACIÓN DIRECTA (intra-módulo):
  Navigator.of(context).push(
    MaterialPageRoute(
      builder: (_) => LeagueDetailPage(event: event, isOwner: isOwner),
    ),
  );

REGLAS:
  - Nunca hacer Navigator.push a una página de otro módulo directamente.
    Usar ModuleRegistry o callbacks del padre.
  - Los módulos no se importan entre sí. La navegación entre módulos pasa
    siempre por ModuleRegistry o AppRouteFactory.

6. AUTENTICACIÓN Y SESIÓN DE USUARIO
================================================================================

FLUJO DE LOGIN
  1. Usuario introduce email y contraseña en LoginPage.
  2. POST a ApiEndpoints.login con DioClient.
  3. Backend devuelve { data: { token: "JWT..." } }.
  4. AuthStorage.saveToken(token)     → persiste en SharedPreferences.
  5. UserSession.loadFromToken(token) → decodifica el JWT (sin librería externa)
                                        y guarda el UserEntity en memoria.
  6. Navigator.pushAndRemoveUntil → HomePage.

FLUJO EN COLD START
  1. main.dart llama _AppRouter._initSession().
  2. AuthStorage.hasToken() → true si hay token guardado.
  3. UserSession.loadFromStorage() → restaura el UserEntity desde SharedPreferences.
  4. FutureBuilder muestra LoginPage o HomePage según el resultado.

ACCEDER AL USUARIO ACTUAL
  UserSession.current         → UserEntity? (null si no autenticado)
  UserSession.isAuthenticated → bool

USERSESSION (core/services/user_session.dart)
  Singleton estático. El JWT es decodificado manualmente (Base64URL sin padding).
  Extrae: id, idRole, firstName, middleName, lastName, secondLastName,
          username, email.

LOGOUT
  await AuthStorage.deleteToken();
  await UserSession.clear();
  Navigator.pushAndRemoveUntil → LoginPage

7. NETWORKING (DioClient)
================================================================================

lib/core/network/dio_client.dart

DioClient encapsula Dio. NUNCA instancies Dio directamente en un servicio.

  class DioClient {
    late final Dio _dio;

    DioClient() {
      _dio = Dio(BaseOptions(
        baseUrl: AppConfig.baseUrl,
        connectTimeout: Duration(seconds: 20),
        receiveTimeout: Duration(seconds: 20),
        headers: {'Content-Type': 'application/json'},
      ));

      _dio.interceptors.add(
        InterceptorsWrapper(onRequest: (options, handler) async {
          final token = await AuthStorage.getToken();
          if (token != null) options.headers['Authorization'] = 'Bearer $token';
          handler.next(options);
        }),
      );

      _dio.interceptors.add(KeyFormatInterceptor());
    }

    Future<Response> get(String path, {Map<String, dynamic>? queryParams}) => ...
    Future<Response> post(String path, {dynamic data}) => ...
    Future<Response> put(String path, {dynamic data}) => ...
    Future<Response> delete(String path) => ...
  }

API_ENDPOINTS (core/network/api_endpoints.dart)
  Todas las URLs en un único lugar. Nunca escribir strings de URL en servicios.

  class ApiEndpoints {
    static String get baseUrl => AppConfig.baseUrl;

    // Auth
    static const String login    = '/users/auth/login';

    // Eventos
    static const String events = '/events';
    static String eventsByType(String typeId)                      => '/events/by-event-type/$typeId';
    static String eventsByTypeAndUser(String typeId, String userId) => '/events/by-event-type/$typeId/by-user/$userId';

    // Teams-Events (inscripción de equipos en eventos)

    static const String teamsEvents                  = '/teams-events';

  }

MANEJO DE RESPUESTAS DEL BACKEND
  El backend puede devolver la lista directamente o envuelta en un objeto:
    final raw = response.data;
    final List<dynamic> list = raw is List ? raw : (raw['data'] as List);

  Siempre manejar ambos formatos en los datasources para no romper ante
  cambios del backend.

8. INYECCIÓN DE DEPENDENCIAS (GetIt)
================================================================================

lib/core/di/service_locator.dart

GetIt actúa como Service Locator. Se usa para:
  - Servicios que deben ser singletons y no necesitan contexto de Widget.
  - Estado global que debe sobrevivir entre navegaciones (EventsNotifier).

REGISTRO ACTUAL
  final getIt = GetIt.instance;

  void setupServiceLocator() {
    // Servicios de datos (lazy singletons)
    getIt.registerLazySingleton<LeagueDetailService>(() => LeagueDetailService());
    getIt.registerLazySingleton<TeamsService>(() => TeamsService());
    getIt.registerLazySingleton<CourtsService>(() => CourtsService());

    // Estado de eventos por tipo de evento (named instances)
    getIt.registerLazySingleton<EventsNotifier>(
      () => EventsNotifier(LeagueService()),
      instanceName: 'leagues',
    );
  }

USO EN UN WIDGET O SERVICIO
  final _service = getIt<LeagueDetailService>();
  final _notifier = getIt<EventsNotifier>(instanceName: 'leagues');

CUÁNDO USAR GetIt VS CREAR INSTANCIA DIRECTA
  Usar GetIt cuando:
    - El servicio debe ser singleton (una sola instancia en toda la app).
    - El estado debe sobrevivir entre navigaciones (ej. EventsNotifier).
    - El servicio es usado por múltiples widgets no relacionados en el árbol.

  Crear instancia directa (final _service = MyService()) cuando:
    - El servicio es usado únicamente en ese widget y no necesita compartirse.
    - Su ciclo de vida puede seguir al del widget.

AGREGAR UN NUEVO SINGLETON
  1. Crear el servicio o notifier.
  2. En setupServiceLocator() agregar:
       getIt.registerLazySingleton<MiServicio>(() => MiServicio());
  3. Usar en widgets: getIt<MiServicio>().

9. GESTIÓN DE ESTADO (Provider + ChangeNotifier)
================================================================================

La app usa Provider + ChangeNotifier para estado reactivo. NO usa BLoC
(aunque las carpetas application/bloc están scaffoldeadas para el futuro).

PATRÓN ESTÁNDAR — EventsNotifier

  class EventsNotifier extends ChangeNotifier {
    final EventService _service;

    List<EventModel> _all     = [];
    Set<String>      _myIds   = {};
    bool             _loading = false;
    String?          _error;
    DateTime?        _lastFetched;

    static const _ttl = Duration(minutes: 3);   // Caché de 3 minutos

    EventsNotifier(this._service);

    // Getters inmutables (nunca exponer la lista mutable directamente)
    List<EventModel> get all  => List.unmodifiable(_all);
    Set<String>  get myIds    => Set.unmodifiable(_myIds);
    List<EventModel> get mine => _all.where((e) => _myIds.contains(e.id)).toList();
    bool get loading          => _loading;
    String? get error         => _error;

    bool get _isFresh =>
        _lastFetched != null && DateTime.now().difference(_lastFetched!) < _ttl;

    // load con TTL y force para el botón de refresh manual
    Future<void> load({bool force = false}) async {
      if (!force && _isFresh) return;   // Cache hit → no recarga
      _loading = true;
      _error   = null;
      notifyListeners();
      try {
        final results = await Future.wait([_service.getAll(), _service.getMyIds()]);
        _all          = results[0] as List<EventModel>;
        _myIds        = results[1] as Set<String>;
        _lastFetched  = DateTime.now();
      } catch (_) {
        _error = 'error';
      } finally {
        _loading = false;
        notifyListeners();
      }
    }

    Future<EventModel> create(Map<String, dynamic> data) async { ... notifyListeners(); }
    Future<EventModel> update(String id, Map<String, dynamic> data) async { ... }
    Future<void> delete(String id) async { ... }
    Future<void> silentReload() async { /* sin _loading, sin notificación de error */ }
  }

CÓMO PROVEER EL NOTIFIER

  OPCIÓN A — Singleton de GetIt (recommended para estado que sobrevive entre
             navegaciones):
    // En la page de módulo:
    return ChangeNotifierProvider.value(
      value: getIt<EventsNotifier>(instanceName: 'leagues'),
      child: EventTypePage(...),
    );

  OPCIÓN B — Nueva instancia local (para estado que vive con la pantalla):
    return ChangeNotifierProvider(
      create: (_) => MiNotifier(),
      child: MiPage(),
    );

  REGLA: Si el notifier está registrado en GetIt, SIEMPRE usar
  ChangeNotifierProvider.value (no create), para no crear una segunda
  instancia y perder el estado cacheado.

CÓMO CONSUMIR EL ESTADO

  // Reconstruye solo cuando cambia el estado:
  Consumer<EventsNotifier>(
    builder: (context, notifier, _) => _buildBody(notifier),
  )

  // Lee sin suscribirse (no reconstruye):
  context.read<EventsNotifier>().load(force: true)

  // Lee y se suscribe (reconstruye en cada cambio):
  context.watch<EventsNotifier>().loading

CUÁNDO CREAR UN NOTIFIER NUEVO
  - Cuando la pantalla tiene estado complejo que muchos sub-widgets necesitan.
  - Cuando el estado debe sobrevivir entre navegaciones (regístralo en GetIt).
  - Para estado simple de un solo widget, usar setState() directamente.

PATRÓN SIMPLE CON setState (para widgets sin notifier propio)
  bool _loading = true;
  String? _error;
  List<T> _items = [];

  // Los tres estados se traducen siempre en:
  if (_loading)        return const Center(child: CircularProgressIndicator(...));
  if (_error != null)  return ErrorRetry(message: _error!, onRetry: _load);
  if (_items.isEmpty)  return EmptyState(title: '...', onAdd: _openCreate);
  return ListView.builder(...);

  - Las claves de éxito siguen: 'modulo.success_accion' (ej. 'leagues.success_created').

  }

SERVICIO DATASOURCE ESTÁNDAR
  class MiModuloService {
    final DioClient _client = DioClient();

    Future<List<MiModel>> getAll() async {
      final response = await _client.get(ApiEndpoints.miModulo);
      final raw = response.data;
      final List<dynamic> list = raw is List ? raw : (raw['data'] as List);
      return list.map((e) => MiModel.fromJson(e as Map<String, dynamic>)).toList();
    }

    Future<MiModel> create(Map<String, dynamic> data) async {
      final response = await _client.post(ApiEndpoints.miModulo, data: data);
      return MiModel.fromJson(response.data is Map ? response.data : response.data['data']);
    }
  }

  class MiPage extends StatefulWidget {

  class _MiPageState extends State<MiPage> {
    late final MiService _service;
    List<MiModel> _items = [];

    String? _error;

    @override

      super.initState();

    Future<void> _load() async {

      ));
